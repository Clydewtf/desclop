# Контракт MVP-редактора плана — Beta.2

## Решение

В beta.2 пользователь редактирует существующий план только в явном режиме
**Edit plan** внутри Planner. Обычный Planner остаётся спокойной картой
работы: он показывает прогресс, Resume-first контекст и переход к задаче, но
не показывает случайно доступные destructive-действия.

Новый план по-прежнему создаётся существующим путём **Import Plan → Preview
import → Import**. Edit plan не открывает второй Markdown-редактор, не
перезаписывает импортированный план Markdown-файлом и не создаёт «черновик
плана» вне локальной модели данных.

## Границы beta.2

В beta.2 входят локальные изменения названия плана, этапов, задач и пунктов
чек-листа. Каждая сохранённая операция меняет только затронутые сущности,
сохраняет их стабильные ID и не стирает привязанную историю.

Не входят:

- совместное редактирование, роли, комментарии нескольких пользователей и
  облачная синхронизация;
- свободная замена существующего плана новым Markdown-текстом;
- отдельный экран или параллельный редактор Markdown;
- drag-and-drop в первой версии редактора: для порядка используются явные
  действия **Move up** / **Move down**;
- перенос этапов между планами, перенос checklist item между задачами,
  splitting/merging задач, массовое редактирование и восстановление
  удалённых сущностей;
- изменение статуса задачи, active task, next step, заметок, work reviews,
  Inbox или Git-связей из Edit plan. Это остаётся в существующих рабочих
  поверхностях.

## Допустимые операции

Здесь **move** меняет родительскую сущность, а **reorder** меняет только
позицию среди соседей того же родителя.

| Уровень | Create | Rename / edit | Move | Reorder | Delete |
| --- | --- | --- | --- | --- | --- |
| План | Только через Import Plan; пустой план из Edit plan не создаётся. | Можно менять title; у плана нет отдельного description. | Не применимо: план принадлежит проекту. | Можно менять порядок планов внутри одного проекта. | Не входит в beta.2. Завершённый план можно скрыть текущим non-destructive действием; постоянное удаление — отдельное решение жизненного цикла планов. |
| Этап | Можно добавить в текущий план. | Можно менять title и description. Status вычисляется системой и вручную не редактируется. | Между планами не переносится. | Можно менять порядок этапов в текущем плане. | Только пустой этап без задач; каскадное удаление задач не допускается. |
| Задача | Можно добавить в выбранный этап. | Можно менять title и description. Status, active task, next step и рабочая история не редактируются здесь. | Можно перенести в другой этап того же плана, сохранив ID, status, чек-лист и связанную историю. | Можно менять порядок задач в одном этапе. | Только неактивную задачу без notes, work entries, Inbox-связей и Git-связей. Её собственные checklist items удаляются после явного подтверждения. |
| Checklist item | Можно добавить в выбранную задачу. | Можно менять title и description. Завершённость меняется обычным рабочим действием, а не Edit plan. | Между задачами не переносится. | Можно менять порядок внутри текущей задачи. | Можно удалить после явного подтверждения; удаление не меняет status задачи. |

Названия обязательны после `trim`: пустое или состоящее из пробелов название
не может попасть в сохранённый план. Совпадающие названия допустимы —
идентичность задаётся ID, а не текстом.

## UX режима Edit plan

1. Пользователь открывает выбранный или текущий план в Planner и нажимает
   **Edit plan**.
2. Planner переходит в один режим редактирования для одного плана. Поля,
   кнопки добавления, удаления и **Move up / Move down** появляются только
   там; обычный режим не меняется.
3. Изменения остаются локальным draft до **Save**. Нет скрытого autosave, нет
   записи в SQLite при каждом вводе и нет отдельного состояния draft в
   localStorage.
4. **Save** применяет валидный набор изменений к локальному источнику истины.
   Если запись не удалась, UI не должен показывать частично сохранённый
   результат: он объясняет ошибку и оставляет draft доступным для исправления
   или отмены.
5. **Cancel** без изменений сразу возвращает обычный Planner. При изменениях
   он спрашивает подтверждение на discard; подтверждённая отмена не вызывает
   локальную команду и возвращает последнее сохранённое состояние.
6. Переход к другой вкладке, другому плану, проекту или закрытие экрана с
   несохранённым draft показывает тот же выбор: **Save**, **Discard** или
   **Stay**. Черновик не восстанавливается после перезапуска приложения.
7. После Save или Cancel фокус возвращается к заголовку редактируемого плана
   или к действию **Edit plan**, если план больше недоступен.

## Безопасность данных и порядок

- Переупорядочивание меняет `position`, а не пересоздаёт сущности. Перенос
  задачи меняет её `stage_id` и позиции затронутых соседей в одной локальной
  транзакции.
- Перенос задачи сохраняет её status, checklist, notes, work entries, Inbox,
  Git-связи, next step и stable ID. После сохранения Today и Resume Brief
  перечитывают локальный ProjectPlanPayload.
- Удаление не может молча стереть рабочую историю. История включает notes,
  work entries, привязки Inbox и Git-связи; active task также нельзя удалить,
  пока пользователь явно не выберет новую active task или не очистит её.
- Если пользователь пытается удалить этап с задачами, вместо каскадного
  удаления он должен сначала перенести или безопасно удалить задачи.

## Сообщения, валидация и отмена

UI beta.2 остаётся англоязычным, поэтому ниже закреплены короткие целевые
сообщения. Техническая причина может быть записана только в diagnostics, но не
показывается вместо следующего действия пользователя.

| Ситуация | Сообщение и действие |
| --- | --- |
| Пустое название | `Enter a name before saving.` Фокус остаётся в соответствующем поле. |
| Неудачное сохранение | `Couldn't save plan changes. Nothing was changed. Try again.` Draft остаётся открыт. |
| План изменился во время редактирования | `This plan changed while you were editing. Reload it before saving your changes.` Пользователь может reload или отменить draft. |
| Удаление этапа с задачами | `Move or remove this stage's tasks before deleting the stage.` Каскадного удаления нет. |
| Удаление задачи с историей | `This task has work history, notes, Inbox items, or linked commits and can't be deleted. Complete, move, or hide it instead.` |
| Удаление active task | `Choose a new active task or clear it before deleting this task.` |
| Край порядка | `This item is already first.` / `This item is already last.` Кнопка также disabled, когда это возможно определить заранее. |
| Есть несохранённые изменения | `Discard unsaved changes? Your saved plan will stay unchanged.` Действия: **Save**, **Discard**, **Stay**. |

## Критерии для следующих реализаций

- В UI существует только один вход в структурное редактирование: **Edit plan**
  в Planner.
- Все CRUD/reorder команды соответствуют матрице выше; неподдерживаемая
  операция не получает скрытый обходной путь.
- Save/Cancel и обработка конфликтов не уничтожают введённый текст или рабочую
  историю.
- После успешного изменения Planner, Today, Task Detail и Resume Brief читают
  одинаковое локальное состояние.
